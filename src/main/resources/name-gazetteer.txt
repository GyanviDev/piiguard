# Supplementary name lexicon.
#
# WHY THIS FILE EXISTS
# --------------------
# The OpenNLP person model (en-ner-person.bin) is trained predominantly on English-language
# newswire, so its notion of "what a name looks like" is drawn from a Western distribution.
# Measured on this system it redacts "John Smith" and "Michael Johnson" reliably and misses
# "Priya Sharma" and "Rahul Verma" completely — not occasionally, entirely.
#
# For a product deployed in India that is not a rough edge, it is the failure mode that
# matters most: the tool works for the names it was demoed with and silently forwards the
# names of the actual users. A statistical model inherits the demographics of its training
# corpus, and pretending otherwise is how bias becomes a security defect.
#
# A curated lexicon is the honest supplement. It does not generalise the way a model does —
# it only knows what is written here — but for a bounded, well-documented name distribution
# that is exactly the right trade: perfect recall on the listed entries, zero on the rest,
# and no guessing in between. The model still handles everything outside this list.
#
# FORMAT
#   One entry per line. Blank lines and lines starting with # are ignored.
#   Matching is case-sensitive on the first letter (a capitalised token), so ordinary
#   lower-case prose containing the same string is not redacted.
#
# EXTENDING
#   This is a resource file, not source, so a deployment can extend it for its own locale
#   without recompiling. Add entries that are unambiguously names; avoid tokens that are
#   also common nouns, because a false positive corrupts a legitimate prompt.
